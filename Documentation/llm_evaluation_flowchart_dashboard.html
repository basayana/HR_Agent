Concept Paradigm

Model Evals vs. Application Evals

  • Model Evals: Benchmarking base foundation models (e.g., GPT-4 vs. Claude 3 vs. Llama 3) on broad skills like MMLU, GSM8K, HumanEval.
  • Application Evals: Evaluating your specific end-to-end LLM application logic (RAG pipeline, agents, custom prompts, tool calling).
Risk Analysis

Component vs. Workflow Failures

Component-level Failures: Bad chunking, poor embedding retrieval, incorrect prompt formatting, parser errors.
Workflow-level Failures: Hallucinations in context synthesize, agent loop divergence, incorrect tool routing despite accurate sub-component outputs.
Why Multiple Evaluation Pipelines Are Necessary

A single global metric (e.g., overall accuracy) masks granular bugs. You need independent evaluation pipelines for: Retrieval Accuracy, Faithfulness/Groundedness, Answer Relevance, and Safety Guardrails.

Key Characteristics

Controlled Static Testing

  • Runs pre-release before live user impact.
  • Uses high-quality curated Golden Datasets.
  • Determinism & repeatable test conditions.
  • Fast iteration cycle during dev.
Primary Goal

Regression & Risk Avoidance

  • Prevents breaking changes when updating prompts.
  • Ensures model upgrades don't cause drift.
  • Guards against legal/hallucination disasters.
Evaluation Methods

Automated & LLM-as-a-Judge

  • Exact match / Regex / Code Execution.
  • Semantic Similarity (Embeddings).
  • LLM-as-a-Judge (GPT-4 scoring against rubrics).
Real-World Failures Due to Missing Offline Evals
Air Canada Refund Incident

An un-evaluated chatbot promised a customer a retroactive bereavement discount contrary to official airline policy. The court ruled the airline liable for the chatbot's hallucination.

Chevrolet Dealership Glitch

Users prompt-engineered a dealership bot into agreeing to sell a $70,000 car for $1. Proper offline red-teaming and system-prompt evals would have caught this prompt vulnerability.

Shadow Deployment

Route live user queries to the new candidate model/prompt in parallel without showing the response to the user. Compare candidate output with production output in real time.

A/B Testing / Canary

Direct a small percentage (e.g., 5%) of live traffic to the new version. Measure engagement, conversion, and online satisfaction metrics before full rollout.

Runtime Guardrails

Input and output filtering layers (e.g., NeMo Guardrails, Guardrails AI) to block toxic inputs, PII leaks, and off-topic prompts dynamically before LLM response generation.

Telemetry Category 1

CAPTURED METRICS (Direct System Logs)

Raw operational data emitted directly during runtime without additional AI processing.

Latency / TTFT Time To First Token & Total Roundtrip

Telemetry Category 2

COMPUTED METRICS (Derived / Evaluated)

Metrics calculated async via post-processing, background LLM judges, or NLP models.

Groundedness Score Is answer supported by retrieved context?
Toxicity & Sentiment Safety classifier score (0.0 to 1.0)
Context Precision/Recall Vector search quality verification
Semantic Similarity Embedding distance from expected domain

User Feedback Signals

Explicit Feedback

Direct action taken by the user to rate quality:

  • Thumbs Up / Thumbs Down clicks
  • Star ratings (1-5)
  • Textual bug/feedback comments
  • "Regenerate response" button click
Implicit Signals

Behavioral proxies inferred from user actions:

  • Copy response to clipboard (High Quality Signal)
  • Dwell time on response page
  • Immediate edit or re-prompt (Frustration Signal)
  • Session abandonment rate
The Continuous Data Flywheel (Online to Offline Loop)

Online evaluation isn't just a dashboard—it feeds back into product quality. Low-scoring online queries (explicit thumbs down or low computed groundedness) are automatically flagged, anonymized, human-reviewed, and added to the Offline Golden Dataset. This prevents future regressions on live failure cases.

Metric Trade-Off Dilemmas

Optimizing for one metric often degrades another. For example, enforcing high safety guardrails may decrease response conciseness or increase latency. Evaluation dashboards must visualize Pareto frontiers rather than single scores.

Regression Detection Strategy

A system prompt update might fix 10 complex edge cases but quietly break 2 core simple queries. Offline evaluation pipelines compare output performance test-by-test to flag localized regressions before release.
