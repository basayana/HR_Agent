LLM Evaluation Lifecycle & Core Tooling

Pre-deployment offline testing vs. post-deployment online production telemetry.

Offline Evals (Pre-Deployment)

Static Test Sets • Regression Prevention

Executed during training, fine-tuning, or prompt engineering phases before releasing a model version to production. Evaluates against standardized ground-truth benchmark datasets.

  • Controlled & Repeatable: Uses deterministic parameters ($T=0$) for baseline comparison.
  • Key Objective: Catching hallucination bugs, format failures, and capability regressions early.

Online Evals (Post-Deployment)

Continuous Telemetry • Real User Input

Continuous evaluation on live production traffic logs. Captures user interactions, latency spikes, monetary costs, and actual customer feedback.

  • Real-World Drift Detection: Monitors edge cases and out-of-distribution prompts from real users.
  • Asynchronous Scoring: Utilizes LLM-as-a-Judge and guardrails asynchronously on sampled logs.

Logging & Telemetry Classification

1. Directly Captured Metrics
  • Input Prompts & System Messages Raw Text Logs
  • Token Utilization Prompt / Completion Tokens

Code Generation Metrics: pass@1 vs. pass@k

Measuring code synthesis accuracy through single-attempt pass rates and multi-candidate combinatorics.

pass@1 (Pass at 1)

Single-Shot Accuracy

Evaluates whether the very first code candidate generated by the model passes 100% of the hidden execution unit test cases for a problem.

Standard Formula:
\(\text{pass@1} = \frac{\text{Number of Problems Passed on 1st Attempt}}{\text{Total Number of Problems}}\)
Run Config: Uses Temperature \(T = 0.0\) (Greedy Decoding) for deterministic single-shot testing.
Primary Use Case: Copilot / Cursor real-time auto-complete where immediate working code is required.

pass@k (Pass at k, where k > 1)

Probabilistic Upper Bound

Generates \(n\) total candidate samples per problem (\(n \ge k\)). Measures the probability that at least 1 out of \(k\) chosen samples passes all unit tests.

Unbiased Estimator (HumanEval Paper):
\(\text{pass@k} := \mathbb{E}_{\text{problems}} \left[ 1 - \frac{\binom{n - c}{k}}{\binom{n}{k}} \right]\)
Where \(n\) = total generated samples, \(c\) = number of passing samples (\(c \le n\)).
Run Config: Requires high diversity sampling (\(T = 0.7 - 0.8\), Top-\(p = 0.95\)).
Primary Use Case: Problem-solving upper bounds with reranking, majority voting, or automated test filters.

Evaluation Hyperparameters & Run Configuration

Standardizing execution parameters to guarantee benchmark reproducibility and comparability.

Temperature (\(T\))

Controls output probability distribution flatness during token sampling.

  • \(T = 0.0\) (Greedy Decoding): Picks top probability token. Essential for deterministic offline benchmarks (MMLU, pass@1).
  • \(T = 0.7 - 0.8\) (Creative / Diverse): Increases generation entropy. Required for pass@100 evaluation to explore diverse solutions.

Top-p (Nucleus Sampling)

Truncates sampling pool to the smallest set of tokens whose cumulative probability sum exceeds threshold \(p\).

  • Top-p = 0.95: Filters out the tail-end 5% lowest-probability improbable tokens, preventing nonsensical generations while retaining output variety.

Few-Shot Prompting (\(k\)-shot)

Determines how many solved exemplar pairs are included in the evaluation context prior to the question query.

  • 0-shot: Direct question answering without examples. Tests raw instruction adherence.
  • 5-shot: Supplies 5 solved examples (e.g., standard MMLU baseline config).

System Prompt Standardization

Defines model role, constraints, and step-by-step reasoning instructions (Chain-of-Thought / CoT).

  • Impact: Changing punctuation or whitespace in system prompts can alter benchmark scores by up to 5–10%. Must be held constant across runs.

Quality Dimensions & Alignment Measurements

Multi-dimensional evaluation criteria for safety, truthfulness, and operational performance.

Truthfulness

Evaluates whether generated outputs correspond to real-world factual ground truth without inventing unverified facts.

Benchmark: SimpleQA, TruthfulQA
Faithfulness (RAG Context)

Measures whether output assertions are strictly grounded in retrieved context documents without extrapolating outside facts.

Framework: Ragas Context Precision
Helpfulness & Instruction

Assesses how accurately the model satisfies complex prompt constraints, format rules (JSON schema), and task requirements.

Evaluation: IFEval / G-Eval Rubric
Harmlessness & Refusal

Measures safety guardrail robustness against toxic outputs, hate speech, cyberattack instructions, and illegal prompts.

Framework: HarmBench / Red Teaming
Calibration & Confidence (ECE)

Determines whether a model's self-reported certainty probability matches its true accuracy rate (Expected Calibration Error).

Metric: Expected Calibration Error
Robustness & Perturbation

Measures output consistency when prompts undergo minor typographical errors, rephrasing, or adversarial formatting shifts.

Method: Adversarial Perturbation
